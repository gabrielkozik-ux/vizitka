## 2. Vyřešené kolize (stejný selektor 2× s překrývající se property)

Devět míst, kde výsledek závisel na pořadí v souboru. Sloučeno do jednoho
pravidla s **hodnotou, která reálně vyhrávala** — vzhled nezměněn:

| Selektor | Co bylo špatně |

| `.nav-logo` | `color` duplicitně (i v `h1..h6, .nav-logo`) |
| `.cta-container` | `margin-bottom` 40px vs 50px |
| `.form-container` | `margin` 40px auto 0 vs 0 auto |
| `.article-content` | `padding` 30px 40px 30px 10px vs 20px 0 |
| `.article-content h2` | `margin-top` 0 vs 40px |

| `.article-image-main` | plně přebito |
| `.prev` / `.next` | `border-radius` řešen přepisem v pořadí, teď explicitně |

U formuláře platilo, že `.form-container input` (vyšší specificita) přebíjelo
`.form-input`. Deklarace v `.form-input` byly z poloviny mrtvé. Sloučeno na
jeden zdroj pravdy s hodnotami, které se reálně renderovaly:
`border: 2px solid #e2e8f0`, `padding: 12px 15px`, `font-family: Inter`.

## 3. Zrušené `!important` (všech 5)

Byly tam kvůli tomu, že se globální `h1 { font-size: 2.5em !important }`
na mobilu bil s `.hero h1` a `.article-header h1`, které se proti tomu musely
bránit dalším `!important`.

Ověřeno, že **každý `<h1>` na webu je v `.hero`, `.article-header` nebo
`.page-header`** — globální pravidlo tedy dopadalo jen na `.page-header h1`.
Nahrazeno explicitním `.page-header h1 { font-size: 2.5em }` a `!important`
zmizely všechny. Renderování identické.

`.active-link` → `.nav-links a.active-link` (specificita místo `!important`).

## 4. Nová struktura `style.css`

Obsah nahoře v souboru, 16 sekcí, **každá komponenta včetně své responsivity
na jednom místě**. Dřív se `.hero` řešilo na třech místech a mobilní chování
bylo v jednom 117řádkovém `@media` bloku na konci, který míchal nav, hero,
akce, blog i patičku.

Konvence zapsané do hlavičky souboru:

- Jeden selektor = jedno místo. Žádné "pozdější pravidlo to přebije".
- Breakpointy jen 680 / 768 / 900 / 1024 px.
- Žádné `!important`.

Tři odložené `FIX:` bloky z konce souboru jsou začleněné do svých sekcí
(mobilní nav článků → sekce 4, ikony v článku → sekce 11).

## 5. Fonty

- Lora se tahala `@import`em *uvnitř* `style.css` → řetězený požadavek,

- Všech 103 souborů má teď identický, jediný font request.
- Odstraněno 8 duplicitních `preconnect` tagů.

## 6. Mrtvé skripty

- **smsticket.cz widget** (`SaleAnchorMini.js`) — `main.js` ho vkládal na

## Co jsem NEUDĚLAL a proč

### Čtyři osiřelé články

Tyhle čtyři **nepoužívají `style.css` vůbec** — mají 160 řádků inline `<style>`
se starou paletou (`#0a2342` + tyrkysová `#2ca58d`, font Roboto):

- `blog/2025/cs-tech-summit-2025/cs-tech-summit-2025.html` (+ `-en`)
- `blog/2025/firemni-kultura-alveno/firemni-kultura-alveno.html` (+ `-en`)

Vypadají jako z jiného webu. Migrace na `style.css` je správný krok, ale
**změní jejich vzhled** a nemůžu ji vizuálně ověřit. Samostatný úkol.

### Pravděpodobný bug v blogových kartách

`.article-content h2` má `margin-top: 40px` a `.article-card .article-content h2`
si ho nepřepisuje → **nad každým titulkem karty v blogu je 40px mezera**.
Zachoval jsem současné chování. Oprava je jeden řádek:

```css
.article-card .article-content h2 { margin-top: 0; }
```

Řekni a přidám to.

### Ztracená animace focus ringu

`.form-input` měla `transition: border-color, box-shadow`, ale `.form-container input`
ji přebíjelo na jen `border-color` → focus ring naskakuje skokem. Zachoval jsem
současný stav. Oprava = přidat `box-shadow` do transition.

## Než merguješ

### Nejdřív srovnej konce řádků

`git status` hlásí 121 změněných souborů / 20 240 vložení = 20 240 smazání.
To nejsou moje změny — pracovní kopie má CRLF, HEAD má LF. Bez tohohle
kroku se v diffu nedá nic přečíst:

```bash
printf '* text=auto eol=lf\n*.png binary\n*.jpg binary\n*.ico binary\n' > .gitattributes
git add --renormalize .
git commit -m "chore: normalizace koncu radku na LF"
```

Pozor: v `.git/` zůstal `index.lock` (0 B). Smaž ho, jinak git nepustí commit:
`del .git\index.lock`
